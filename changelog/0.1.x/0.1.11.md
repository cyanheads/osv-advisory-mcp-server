# 0.1.11 — 2026-07-11

## Fixed

- **`osv_get_vulnerability`, `osv_query_package`** — affected entries with no package identity (GIT-range-only CVE records) are no longer dropped; ranges with more than one introduced/fixed interval no longer collapse to the last event only. ([#13](https://github.com/cyanheads/osv-advisory-mcp-server/issues/13))
- **`osv_query_package`, `osv_query_batch`** — an OSV response carrying a `next_page_token` is no longer treated as a complete or clean result; `osv_query_package` now follows the token up to `OSV_QUERY_MAX_PAGES` pages, and both tools disclose truncation instead of reporting a false clean. ([#15](https://github.com/cyanheads/osv-advisory-mcp-server/issues/15))

## Added

- **`osv_get_vulnerability`, `osv_query_package`** — affected ranges gain optional `repo` (GIT source URL) and `events[]` (ordered `introduced`/`fixed`/`last_affected`/`limit` boundaries), plus `versions[]` (explicitly enumerated affected versions), alongside the existing collapsed `introduced`/`fixed`/`lastAffected` scalars. ([#13](https://github.com/cyanheads/osv-advisory-mcp-server/issues/13))
- **`osv_get_vulnerability`** — optional `withdrawn` field (ISO 8601 timestamp) surfaces retracted advisories; `content[]` renders a `⚠️ WITHDRAWN` notice. ([#14](https://github.com/cyanheads/osv-advisory-mcp-server/issues/14))
- **`osv_query_package`, `osv_query_batch`** — `truncated` boolean on each result (batch also gains a summary `truncatedCount`) flags an incomplete fetch. New `OSV_QUERY_MAX_PAGES` env var (default `10`) bounds pages followed per query. ([#15](https://github.com/cyanheads/osv-advisory-mcp-server/issues/15))

## Changed

- **`osv_query_batch`** — summary `cleanCount` now excludes truncated rows; a row with no findings but a pending page is reported separately, not counted as clean. ([#15](https://github.com/cyanheads/osv-advisory-mcp-server/issues/15))
