# 0.1.15 — 2026-09-24

## Added

- **`severitySource`** on `osv_query_package` vulns and `osv_get_vulnerability` — `{ type, score, computedScore? }` naming the entry `severityLabel` came from; `null` exactly when the label is ([#17](https://github.com/cyanheads/osv-advisory-mcp-server/issues/17)).
- **`affected[].severity`** on `osv_get_vulnerability` — package-level severity entries, rendered under their package in `content[]` ([#17](https://github.com/cyanheads/osv-advisory-mcp-server/issues/17)).
- **`bun run check:ecosystems`** — `scripts/check-ecosystems.ts` probes the OSV schema's `ecosystemName` members, `GIT`, and every catalog entry against live `POST /v1/query`, printing add / withhold / remove lists; exits 1 on drift, 2 on a failed request. Not a devcheck step ([#12](https://github.com/cyanheads/osv-advisory-mcp-server/issues/12)).

## Changed

- **`severityLabel`** — the first source that yields a label wins: `database_specific.severity` in any case (`Medium` → `MODERATE`), an `Ubuntu` priority, then the highest `CVSS_V3`/`CVSS_V4` score computed from the vector as published. Record-level `severity[]` is used, or when empty, the `affected[].severity` of the queried package's entries (every entry in `osv_get_vulnerability`) ([#17](https://github.com/cyanheads/osv-advisory-mcp-server/issues/17)).
- **`osv_get_vulnerability` `id`** — one schema pattern, `^[A-Za-z][A-Za-z0-9_]*-\S(.*\S)?$`, after trimming; wildcards, bare package names, and prefix-only input fail `-32602` before any OSV.dev request. The `vulnerability_not_found` recovery names exact-case matching and the Debian/Ubuntu/SUSE revision suffix ([#23](https://github.com/cyanheads/osv-advisory-mcp-server/issues/23)).
- **`osv_list_ecosystems`** — adds `Homebrew` and `WordPress` (52 entries); the catalog is every schema `ecosystemName` member OSV.dev accepts, plus `GIT`, verified 2026-09-24 ([#12](https://github.com/cyanheads/osv-advisory-mcp-server/issues/12)).

## Fixed

- **`fixedVersions`** (`osv_query_package`, `osv_query_batch`) — lists every `fixed` event of the SEMVER/ECOSYSTEM ranges on the `affected[]` entries matching the queried package, matched as OSV.dev matches the query (base and Ubuntu-variant ecosystems, PEP 503 names on PyPI). Other packages' fixes and GIT commit hashes no longer appear; `affectedRanges` stays complete ([#16](https://github.com/cyanheads/osv-advisory-mcp-server/issues/16)).
- **Package inputs** (`name`, `ecosystem`, `version` on both query tools) — surrounding whitespace is trimmed before the request and the echo, so `" lodash "` no longer returns a false clean result ([#27](https://github.com/cyanheads/osv-advisory-mcp-server/issues/27)).
- **Blank-input rejection** — `""` and whitespace-only values fail with one message per field instead of the same sentence twice ([#25](https://github.com/cyanheads/osv-advisory-mcp-server/issues/25)).

## Security

- **Advisory text in `content[]`** — every OSV-sourced string passes through a render-boundary escape: tag and autolink openers become `&lt;`, non-`http(s)` link destinations and line-leading reference definitions are backslash-escaped, and forged `advisory_summary`/`advisory_text` frame tags are neutralized, fenced code included. `structuredContent` keeps OSV strings verbatim, and `osv_query_package`'s `invalid_ecosystem` message no longer quotes OSV.dev's error text ([#18](https://github.com/cyanheads/osv-advisory-mcp-server/issues/18)).
