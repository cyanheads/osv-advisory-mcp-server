# 0.1.7 — 2026-06-30

## Fixed

- **`osv_query_batch` ecosystem preflight removed** — the static `SUPPORTED_ECOSYSTEMS` allowlist had drifted behind the OSV schema and rejected valid ecosystems (e.g. `Ubuntu:22.04:LTS`) before the request reached OSV. OSV is now the sole authority: an unrecognized ecosystem comes back as a per-package `results[i].error` instead of failing the whole batch. Dropped the tool's `invalid_ecosystem` error contract and the now-dead `OsvApiService.probeEcosystem()`. ([#3](https://github.com/cyanheads/osv-advisory-mcp-server/issues/3))
- **Declared recovery hints reach the wire** — `osv_query_package` and `osv_get_vulnerability` spread `ctx.recoveryFor(...)` into `ctx.fail(...)`, so each `errors[].recovery` populates `structuredContent.error.data.recovery.hint` and the mirrored `content[]` text rather than being dropped. ([#4](https://github.com/cyanheads/osv-advisory-mcp-server/issues/4))
- **`format()` content/structured parity** — `osv_query_batch` renders a Clean Packages section, and `osv_get_vulnerability` renders every reference (previously capped at the first 8 with a `… N more` note). `content[]`-only; output schemas unchanged. ([#5](https://github.com/cyanheads/osv-advisory-mcp-server/issues/5))
- **Stale `osv_query` tool-text references** — replaced with the current `osv_query_package` in `osv_list_ecosystems` and `osv_get_vulnerability` descriptions, the `vulnerability_not_found` recovery string, and `docs/design.md`. ([#8](https://github.com/cyanheads/osv-advisory-mcp-server/issues/8))

## Dependencies
