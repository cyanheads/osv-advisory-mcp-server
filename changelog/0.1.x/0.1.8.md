# 0.1.8 — 2026-06-30

## Added

- **`OSV_BATCH_CONCURRENCY`** — optional env var (positive integer, default `10`) capping the number of concurrent OSV.dev requests issued by `osv_query_batch`. ([#6](https://github.com/cyanheads/osv-advisory-mcp-server/issues/6))
- **Startup config validation** — new `src/config/server-config.ts` validates `OSV_REQUEST_TIMEOUT_MS` (positive number) and `OSV_BATCH_CONCURRENCY` (positive integer) through `parseEnvConfig`; an invalid, zero, or negative value now fails startup with a `ConfigurationError` naming the variable instead of silently falling back to the default. ([#7](https://github.com/cyanheads/osv-advisory-mcp-server/issues/7))

## Changed

- **`osv_query_batch` bounded concurrency** — per-package queries drain through a bounded worker pool (at most `OSV_BATCH_CONCURRENCY` in flight, default `10`) instead of fanning every package out at once, so a 1000-package batch no longer becomes a 1000-request upstream burst. Positional results (`results[i]` ↔ `packages[i]`) and per-package partial-success semantics are unchanged. ([#6](https://github.com/cyanheads/osv-advisory-mcp-server/issues/6))

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.9 → ^0.10.10` — clears the transitive `js-yaml` advisory [GHSA-h67p-54hq-rp68](https://github.com/advisories/GHSA-h67p-54hq-rp68); `bun audit` clean.
