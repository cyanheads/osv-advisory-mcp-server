# 0.1.10 — 2026-07-11

## Added

- **`osv_query_package`** — optional `enrichment.notice` and `enrichment.effectiveQuery` populate on the clean path (no known vulnerabilities): a plain-language notice and a `name@version (ecosystem)` echo, for content-only clients that can't read `structuredContent`. ([#9](https://github.com/cyanheads/osv-advisory-mcp-server/issues/9))
- **`osv_query_batch`** — same `enrichment` block, populated on all-clean and all-errors batches with an aggregate notice and a compact scan summary (`N package(s): X vulnerable, Y clean, Z error(s)`); mixed batches are left unenriched. ([#9](https://github.com/cyanheads/osv-advisory-mcp-server/issues/9))

## Changed

- **`osv_query_batch`** — `content[]` error rows now render the queried `version` (`` `name` @ `version` (ecosystem): error ``), matching `structuredContent.results[i].version`. ([#5](https://github.com/cyanheads/osv-advisory-mcp-server/issues/5))

## Security

- **`osv_query_package`, `osv_query_batch`, `osv_get_vulnerability`** — upstream OSV advisory `summary` text in `content[]` is now wrapped in `<advisory_summary>...</advisory_summary>` (per-vuln in `osv_query_batch`'s listing), framing untrusted, LLM-facing advisory text against prompt injection — the same boundary style `osv_get_vulnerability` already applies to `details`. Empty summaries emit no boundary block. ([#11](https://github.com/cyanheads/osv-advisory-mcp-server/issues/11))
